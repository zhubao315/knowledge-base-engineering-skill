# Incident Response

## 先停手

事故发生时，第一动作不是查根因，而是停止可能扩大损害的自动写入、清理、批量改名。不能停手时，明确标 `BLOCKED`，给操作指令，不声称已执行。

## 应急四联

1. **停手**：暂停写入/清理/生成。
2. **留证**：现场、日志、时间、影响范围、已执行操作。
3. **回滚**：备份/版本历史/快照；恢复须人确认。
4. **复验**：正文完整性、链接、任务状态、指标。

## 分级

| 级别 | 判定 | 响应 | 处置权 |
|---|---|---|---|
| L1 单文件可逆 | 单篇误改、单链断裂 | 当日 | AI 可修，人抽检 |
| L2 批量/链路 | 任务停摆、批量误改 | 1 小时 | 人确认，AI 执行 |
| L3 不可再生 | 手写丢失、核心正文消失 | 立即 | 仅人类 |

## 复盘四问

1. 时间线：最早异常、发现路径、本可发现的窗口。
2. 根因：现象 → 直接原因 → 机制缺口，连问三层。
3. 缺纪律：只写一条最关键的。
4. 回写：落到哪张清单/闸门/Runbook，何时复验。

## 证据

设计存在不等于系统在跑。需要：时间戳、扫描范围、退出码/日志、独立复算或人工抽样。四样缺一，不能报完成。

## 输出

事故记录：四件套 + 影响面 + 补做成本 + 恢复演练结果。
