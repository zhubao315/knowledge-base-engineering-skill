# Permissions

## 四域

| 域 | AI | 人 |
|---|---|---|
| USER 用户认知资产 | 只读；受控追加逐次确认 | 所有者，终审 |
| SYSTEM 系统基础设施 | 可迭代，须变更说明 | 审批，保留回滚点 |
| SHARED 人机协同 | 可创建、可追加 | 抽检、终审 |
| RUNTIME 临时运行时 | 可读写、可清理 | 不介入 |

核心原则：系统更新时，用户资产不被覆盖。隔离的是权限，不是位置。

## 权限矩阵

| 操作 | AI |
|---|---|
| 只读扫描 | 允许（范围内） |
| 新建笔记 | 仅收件箱/草稿区自主 |
| 修改正文 | 需确认 |
| 移动/重命名 | 需变更说明 |
| 批量替换 | 逐文件确认 |
| 物理删除 | **禁止** |
| 版本库操作 | 人类 |
| 改域策略 | 人类 |

## 软归档五步

标记 → 移出主视图 → 保留入口 → 登记台账 → 冷却复核（建议 30 天）。物理清理由人执行。

## 签字点

软归档执行、移动/批量重命名、基线调整、跨域写入。**物理删除不是签字点，因为不在 AI 权限集合内。**

签字必须看到三样：改什么、证据是什么、出错怎么回滚。

## 显式授权五要素

授权人、范围、时限、回滚点、复验记录。一次性、限范围、可撤销。

## 工具层

不要用提示词代替权限：先只挂只读工具；候选写隔离草稿；写入工具按目录/动作限制；审批与执行分离；变更后独立复验。
