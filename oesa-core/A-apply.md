# A — Apply

> 连接才是资产；AI 无删除权；人的主权守在不可逆的一侧。

## 这一段做什么

把资产接入人机协作：语义路由、四域权限、签字点与交付契约。调用不是“多问一句”，是把正确的上下文送到正确的边界里。

## 1. 四域权限

| 域 | 放什么 | AI 默认 | 人类角色 |
|---|---|---|---|
| USER | 个人判断、手写理解、私人记录 | 只读或按授权追加 | 所有者 |
| SYSTEM | 规则、模板、索引、脚本 | 只读；改动走提案 | 规则所有者 |
| SHARED | 团队共用、可引用上下文 | 只读；跨域写入需授权 | 团队负责人 |
| RUNTIME | 缓存、构建产物、临时文件 | 可清理候选，但只出清单 | 运维/所有者 |

跨域写入默认禁止；需要范围、目标、期限。

## 2. 拓扑与语义路由

- 核心区新笔记：入链 ≥1、出链 ≥2；出链优先指向概念、模型、框架。
- 悬空笔记只进收件箱，不硬塞进正库。
- 孤岛三路径：桥接 / 重构 / 清理候选；清理只出候选，不删。
- 断链按频次分档：高频清零，长尾写接受策略。
- 枢纽不是荣誉，是责任；单点故障半径要带口径。

## 3. 签字点

| 动作 | AI 权限 | 停在哪 | 谁放行 |
|---|---|---|---|
| 物理删除 | 无（绝对禁止） | AI 不执行，只出候选 | 无放行人；人手动做并补台账 |
| 软归档执行 | 无（只出候选） | “已软归档，待签字” | 人类所有者 |
| 移动 / 批量重命名 | 需确认 | 变更说明 | 人类所有者 |
| 基线调整 | 无 | 提案 | 人类所有者 |
| 跨域写入 | 无 | 提案 | 人类所有者 |

签字必须看到三样：改什么、证据是什么、出错怎么回滚。

## 4. 输出

- 语义路由计划与链接计划。
- 四域权限表与签字记录。
- 可交付上下文包与来源清单。
- 验收记录：新增断链、内容丢失、口径漂移。

## 停点

- 物理删除：不在权限集合内，没有签字路径。
- 无签字：动作停在建议。
- 批量移动/改名：先出变更说明，不自动执行。
- 调用后无复验：不算闭环。
