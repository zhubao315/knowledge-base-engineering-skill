# S — Standardize

> 摘抄证明见过，模型证明想过，技能原子证明能做；生成通量 ≤ 消化通量。

## 这一段做什么

把过门的内容从“文件”固化成“可调用资产”：定级、提炼、合并、退役。只出候选，不执行不可逆动作。

## 1. L0–L7 消化阶梯

| 级 | 形态 | 判定问题 | 去向 |
|---|---|---|---|
| L0 | 原始输入 | 这是原文/剪藏/流水吗 | 源料区 |
| L1 | 概念 | 能说清是什么、不是什么吗 | 概念层 |
| L2 | 模型 | 能解释一组现象吗 | 模型层 |
| L3 | 框架 | 能指导一组决策吗 | 框架层 |
| L4 | 原则 | 能跨场景迁移吗 | 原则层 |
| L5 | 洞察 | 有个人判断与边界吗 | 洞察层 |
| L6 | 洞察晶体 | 原子化、自包含、可复用吗 | 晶体层 |
| L7 | 技能原子 | 能被 Agent 直接装载执行吗 | Runbook / Skill |

L7 至少写清：触发、输入、步骤、验收、回滚。到不了 L6/L7，不许伪装成“已完成”。

## 2. 正本与合并

- 同主题只留一个正本；其余标“同主题候选”。
- 合并前先确认价值去向；原文、差异、恢复路径都要留。
- 重复分四类：内部整段、正文近重复、真同名、有意镜像；有意镜像不当事故处理。

## 3. 软归档五步

1. **提名**：写原位置、归档位置、理由。
2. **留证**：摘要、来源、关联链接、恢复步骤。
3. **冷却**：至少 30 天，不立刻物理删除。
4. **签字**：人类所有者确认“改什么 / 证据 / 回滚”。
5. **复验**：索引、链接、检索结果不丢。

**产出只写“已软归档，待人类签字”**；AI 不执行归档动作，更不执行物理删除。

## 4. 输出

- 分级清单与正本候选。
- 软归档候选清单（不是删除清单）。
- Runbook / Skill 候选。
- 内容债偿还排期。

## 停点

- 物理删除：不存在此动作。
- 软归档：只出候选，人签字后由人执行。
- 证据不足：`NEEDS_REVIEW`，不硬定级。
- 生成通量大于消化通量：先停新增，再谈提炼。
